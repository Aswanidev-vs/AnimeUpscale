# Plan: PSD Layer Upscaling Support

## Objective
Add support for upscaling Photoshop PSD files by extracting, upscaling, and reassembling each individual layer into a new PSD, preserving layer metadata (name, opacity, blend mode, visibility, position). The PSD pipeline sits **above** the engine layer — the same as the video pipeline — so all engines (realesrgan, realsr, builtin, etc.) gain PSD support without modification.

## Design

The PSD pipeline mirrors the existing video pipeline pattern:
1. Read PSD → extract layers as temporary PNG files
2. Upscale each layer PNG via the requested engine
3. Scale layer positions proportionally
4. Reassemble upscaled layers into a new PSD

### PSD Format Subset
We support the common case: **RGB 8-bit PSDs with RLE-compressed layers**. The PSD format spec (Adobe) is used for parsing/writing:
- File header → Color mode data → Image resources → Layer & mask info → Composite image
- RLE (PackBits-style) compression for channel data
- Layer properties: name, bounds (top/left/bottom/right), opacity, blend mode key, visibility flag, clipping

### Layer Mode (`-layers` flag)
- `visible` (default): upscale only visible layers, preserve them as visible
- `all`: upscale all layers (visible + hidden), preserve visibility state
- A hidden layer that's skipped keeps its original data at original size (not upscaled)

### Position Scaling
Layer coordinates (top/left/bottom/right) are multiplied by the scale factor so relative layout is preserved. E.g., a layer at (100, 100) in a 500×500 image becomes (200, 200) in a 1000×1000 upscaled version.

## Files to Create

### 1. `internal/upscale/psd.go` (~500-700 lines)
PSD binary reader and writer. Key components:

- **Types**: `psdFile`, `psdLayer` structs holding header info, layer metadata, and pixel data
- **`readPSD(path string) (*psdFile, error)`**: 
  - Parse file header (26 bytes)
  - Skip color mode data
  - Skip image resources
  - Parse layer & mask info: layer count, per-layer records, channel data
  - RLE decompression per channel
  - Reconstruct each layer as `*image.NRGBA`
- **`writePSD(path string, psd *psdFile) error`**:
  - Write file header with updated dimensions
  - Write minimal color mode + image resource sections
  - Write layer & mask info with upscaled bounds + metadata + RLE-compressed channel data
  - Write composite image data (merge visible layers)
- **Helpers**: RLE compress/decompress, PackBits encoding

### 2. `internal/upscale/psdpipeline.go` (~150-200 lines)
PSD orchestration layer.

- **`psdPipeline` struct** wrapping `*Manager`
- **`Process(req Request) (Result, error)`**:
  1. Read input PSD → get layers
  2. For each layer to process: write temp PNG → call manager's engine to upscale → read back
  3. Scale layer bounds by scale factor
  4. Write output PSD with upscaled layers
  5. Clean up temp files
  6. Return Result with dimensions of composite

## CLI Interface

```
# Basic PSD upscale (default: upscale visible layers)
au.exe -i design.psd -o design-upscaled.psd -engine realesrgan -scale 4

# Upscale all layers including hidden ones
au.exe -i design.psd -o design-upscaled.psd -layers all -engine realesrgan -scale 4

# Using builtin engine
au.exe -i design.psd -o design-upscaled.psd -engine builtin -scale 2 -sharpen 0.25
```

## Dependencies
**Zero new external Go dependencies.** PSD parsing/writing is implemented using only Go standard library (`encoding/binary`, `image`, `image/color`, `io`, `os`, `compress`). This aligns with the project's `go.mod` philosophy.

## Verification

1. **Build**: `go build -o au.exe .` — must compile cleanly
2. **List engines**: `au.exe -list-engines` — must not break
3. **PSD test**: Create a test PSD with 2-3 layers (different positions, opacities, blend modes) using Photoshop or a tool, then:
   - `au.exe -i test.psd -o out.psd -engine builtin -scale 2`
   - Verify: output is valid PSD, layers preserved at 2x size
4. **Layer mode test**: 
   - `au.exe -i test.psd -o out.psd -layers all -engine builtin -scale 2`
5. **PNG compat**: `au.exe -i image.png -o out.png -engine builtin -scale 2` — must still work unchanged
6. **Video compat**: existing video pipeline must be unaffected
7. **External engine test**: If realesrgan is available, test PSD through it
